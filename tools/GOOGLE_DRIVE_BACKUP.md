# Резервная копия исходников на Google Диске

GitHub Actions по каждому push в `main` и при ручном запуске создаёт ZIP актуального `main` и перезаписывает `3SA2-source-backup.zip` в выбранной папке. Архив создаётся через `git archive`: в нём только файлы из Git, без ключа подписи, локальных настроек и APK. Ранее созданный файл сохраняет свой Google Drive ID и ссылку.

## Первоначальная настройка владельцем Google-аккаунта

Подключение Google Диска в чате не предоставляет постоянный доступ GitHub Actions. Для автоматической работы нужно создать собственный OAuth-клиент в Google Cloud:

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте проект и включите **Google Drive API**. Официальная инструкция: [Google Drive Python quickstart](https://developers.google.com/workspace/drive/api/quickstart/python).
2. Настройте экран согласия OAuth: тип External, контактные данные, добавьте свой Google-аккаунт в тестовые пользователи. Если Google запросит области доступа, добавьте `https://www.googleapis.com/auth/drive`.
3. Создайте **OAuth client ID → Desktop app**, скачайте JSON с данными клиента. Это отдельный файл, не связанный с ключом подписи Android.
4. На своём компьютере с Python 3 скачайте исходники и выполните в папке проекта:

   ```sh
   python tools/authorize_google_drive.py ПУТЬ_К_ФАЙЛУ_КЛИЕНТА.json
   ```

   Откроется вход Google. Войдите в аккаунт — владелец выбранной папки, и разрешите доступ. В текущей папке появится `google-drive-backup-credentials.json`.
5. Откройте на GitHub **Settings → Secrets and variables → Actions → New repository secret**. Имя секрета — `GOOGLE_DRIVE_CREDENTIALS`; значение — всё содержимое `google-drive-backup-credentials.json` (включая фигурные скобки). Сохраните. Файл и его содержимое никому не отправляйте и не загружайте в Git.
6. На вкладке **Actions → Backup sources to Google Drive → Run workflow** вручную запустите первую автоматическую проверку. Успех — зелёный статус и новое время изменения ZIP в Google Диске. После этого push в `main` запускает копирование автоматически.

Секрет предоставляет доступ к данным Google Диска аккаунта, а не только к одной папке: выбранный OAuth scope необходим для замены ранее созданного файла. Сам скрипт изменяет только заранее заданный файл и проверяет его имя и папку. Никогда не добавляйте секрет в открытый репозиторий. Доступ можно отозвать в настройках безопасности Google и удалить секрет на GitHub.

**Срок действия:** Google сообщает, что для внешнего OAuth-приложения в режиме Testing refresh token с доступом к Drive обычно истекает через 7 дней. Нужно проверить требования Google к переводу приложения в Production; без этого авторизацию придётся периодически повторять. См. [документацию Google](https://developers.google.com/identity/protocols/oauth2). Если доступ отозван, истёк или файл перемещён, workflow завершится с ошибкой и не заменит другой файл.
